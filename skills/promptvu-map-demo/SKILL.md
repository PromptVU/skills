# Map the product and plan the demo

Good prompts sit on the right element and tie it to a buyer outcome. You can't do that without knowing the product's screens, and you can't plan a 30 to 45 minute demo without knowing everything the product can show. This skill does both, once per product.

Read first: `references/rules.md`.

Steps in the PromptVu app are written as **bold actions**. How to do each one is in `references/promptvu-app.md`.

## What to do

### 1. Get set up
1. **Get into PromptVu.**
2. Ask the rep which sequence is their best current demo (their Master), unless the knowledge base already says. If they have a recording or transcript of a real demo, use it to learn the order they click through and what they say on each screen.
3. **Find a sequence.** If they have no sequence for this product yet, **Create a sequence** named "[PRODUCT] demo - Master" with the page their demo starts on as the Start URL.
4. **Play a sequence** (the Master). If the product asks for a sign-in, stop and ask the rep to sign in themselves inside PromptVu. Never type a password. Wait until they say they're done.
5. Ask how long their demo usually runs, unless they already said. If they don't know, plan for 30 to 45 minutes.

### 2. Tour the product
Before you map the rep's path, learn the whole product. **Move between pages** through every area in the product's main menu, and one level down in each.

- Only click to move around. Never submit forms, save settings or create or delete anything in the product. If a step needs data entry to continue, stop and ask the rep how they handle it on a live call.
- Skip admin, billing, user management and account settings unless the rep says they demo them.
- If a screen looks empty because there's no sample data, note it. Don't create data to fill it.
- If the product is large, finish the main menu first and tell the rep how far you got.

List every area you found:

| Field | What to write |
|---|---|
| Area | A plain name, like "Pipeline dashboard" or "Reports" |
| Where | How you got there from the start page |
| What it does | One line, in buyer language |
| Buyer outcome | Time saved, revenue gained, costs cut or risk reduced |
| Shows well? | Yes, needs sample data or broken |

### 3. Map the rep's demo
Walk the Master the way the rep demos it, in the order the recording shows. If there's no recording and no Master yet, ask the rep to click through the demo once and tell you the screens.

For each page or screen, record:

| Field | What to write |
|---|---|
| # | Order in the demo |
| Page | A plain name |
| URL | As shown, for reference only |
| What it shows | One line |
| Key elements | The buttons, charts, prices, tables or headings the rep would point at |
| Buyer outcome | Which result this page proves |
| Existing prompts | How many prompts already show on it |
| Same-URL screens | Any tab, pop-up or wizard step that changes the screen without changing the URL |
| Notes | Login walls, slow loads, empty states, anything that could trip up a live demo |

### 4. Compare the two
Put the tour next to the rep's demo and list:

- **Worth adding:** strong areas from the tour the rep never shows, and the buyer outcome each one proves.
- **Worth cutting:** pages in the rep's demo with no clear buyer outcome.
- **Risks:** screens that change without the URL changing, text boxes the rep points at, empty or broken screens.

### 5. Plan the demo
Draft a demo plan that fits the rep's demo length. Leave room for questions: plan about 80% of the time.

| Part | Minutes | Screens | The point to make | Buyer outcome | Priority |
|---|---|---|---|---|---|

Build it from these parts:

1. **Open and agenda** (2 to 3 minutes): confirm what the buyer cares about and what you'll show.
2. **Three or four main sections** (most of the time): each one proves one buyer outcome, in the order that tells the strongest story. Start with the outcome the typical buyer cares about most.
3. **Wrap and next step** (3 to 5 minutes): recap the ROI and agree the next step.

Mark every screen as **must show**, **show if relevant** or **skip**. "Show if relevant" screens are the ones a meeting can add or drop for a specific buyer.

### 6. Check it with the rep
Show the rep the plan, the Worth adding list and the risks. Fix anything they correct. Don't build or change prompts until they approve the plan.

Never change their Master to follow the plan unless they ask. If they want changes for one meeting, those go in a duplicate.

### 7. Save it
Add three parts to the rep's "[PRODUCT] knowledge base": "Product tour", "Demo map" and "Demo plan". Every other PromptVu skill starts from them.

### 8. Wrap up
Tell the rep how many areas you toured, how many pages their demo covers, the top two things worth adding and anything you flagged.
